# Decisions — GATE-2-CP-0002

This checkpoint closes GATE 2 — AGENT RUNTIME. The Gate was delivered and sealed `BLOCKED` in
`GATE-2-CP-0001`, whose decisions, ADRs (`ADR-0020`, `ADR-0021`, `ADR-0022`) and findings
`G2-F-001` to `G2-F-008` stand unchanged; this file records only what the closure decided.

## Why a second checkpoint

`GATE-2-CP-0001` is sealed: its content commit and its evidence commit are tagged
`iacode-checkpoints/GATE-2-CP-0001`, and no sealed checkpoint in this repository has ever been
changed after its tag. Its own `NEXT.md` described the closure as edits inside it, followed by a
seal — but sealing creates that tag, which already exists, and moving it is exactly what the
integrity chain treats as tampering. The operator decided, when asked, that the closure is a new
checkpoint. `GATE-2-CP-0001` is untouched and is now anchored in `.iacode/anchors/checkpoint-chain.json`
by this one (`cmd-0002`).

The closure had first been carried out inside the sealed checkpoint's working copy. That working
copy was restored to its sealed content, the evidence was executed again natively in this
checkpoint's ledger, and everything the first attempt recorded is kept below, byte for byte, under
*Records made against the sealed GATE-2-CP-0001*.

## Decisions taken at closure

**The operator registered OpenAI as a second provider and pointed the live evidence at it.** DevWorld
answered every paid model with `429 RATE_LIMITED` for about fourteen hours. The operator decided,
in this session and in so many words, to use OpenAI instead of waiting, and chose
`openai:gpt-4o-mini`. That is the decision `NEXT.md` reserved for the operator: which model the
project pays for and which one its evidence describes. It was taken by the operator and recorded
here; nothing in the delivery chose a model, and no check was changed to accept one.

What changed is configuration, through the procedure `docs/runbooks/MODEL-GATEWAY.md` documents
for adding a provider: an `openai` entry in `.iacode/policies/providers.json` (the Chat Completions
protocol only, priority 50 below DevWorld's 100), its two variables in `infra/compose/.env.example`
and `infra/compose/docker-compose.yml`, and, in the git-ignored local configuration,
`IACODE_GATEWAY_SMOKE_MODEL` and `IACODE_GATEWAY_DEFAULT_MODEL` set to `openai:gpt-4o-mini` with the
previous DevWorld values kept beside them. No adapter, protocol or routing code changed.

**The automatic fallback the operator first asked for is not configured, and why.** The gateway
already falls back across a route's candidates on `RATE_LIMITED` and `PROVIDER_UNAVAILABLE`; that
is GATE 1 code. Configuring it means giving a route candidates, and GATE 1 row 7.8 keeps every
route empty until a preference has been measured — `test_the_route_policy_asserts_no_measured_preference`
enforces it. Weakening that test to fit a closure is exactly what the contract forbids, so the
chain is left for a decision of its own. It would not have closed this Gate either: the live smokes
name their model explicitly, and an explicit model is never widened into a fallback (row 19.3).

**A refusal names the defect it found.** The envelope parser refused a planner's `content` that
was an array of steps with the sentence it uses for a missing `content`. The one repair quoted that
sentence back and received the same array. The parser is exactly as strict as before; a present
value of the wrong type now has its own reason, `content-not-a-string`, and the runtime contract
states once, for every agent, that `content` is one JSON string. `G2-F-009`.

**A run's log closes before its state does.** Terminal state and terminal event are two commits.
They were written state first, so a reader between them saw a `SUCCEEDED` run whose log never
said so — a live smoke did, once in three runs. Every terminal path now writes the event first:
the engine's three outcomes, the workflow's deadline and unrecoverable paths, and the API's
workflow-could-not-start path, which before this wrote `FAILED` with no terminal event at all.
One transaction for both would be stronger and was not chosen here: it needs a new store operation
and a changed activity contract, which is a change of shape rather than a repair. `G2-F-010`.

**An observation is waited for, not assumed.** The live gateway smoke read Prometheus once, the
instant after its call, while Prometheus scrapes every fifteen seconds; on a freshly rebuilt stack it
failed on a call that had succeeded (`cmd-0004`). The check now waits for the scrape, bounded by
three intervals, and asks only Prometheus — the provider is never called again to make the metric
appear. `G2-F-012`.

**A sealed checkpoint is bound to its own canonical tag.** `GATE-2-CP-0001` was sealed at `BLOCKED`
with `currentCommit` `HEAD`, which that status may keep, and so could never be validated from its
own tag: the historical check turned red the moment this checkpoint anchored it (`cmd-0015`). It
cannot be edited and its tag cannot move. The operator decided that the tooling be repaired rather
than the Gate held: a symbolic HEAD is now bound to the checkpoint's own canonical tag, derived from
its identity — the same binding a named tag gives — and the seal tool refuses a state that does not
name its own tag, so the case cannot recur. `ADR-0023`, `G2-F-013`.

**A control is the class, not the instance.** The full verification's fresh installation failed one
smoke check it could not name (`cmd-0036`). The scenario was made to name failing checks, and its
next run named them: both Prometheus targets `down`, read before the scrape that follows a fresh
start (`cmd-0038`). That is `G2-F-012`'s class in the Foundation smoke, and `GRD-0051` had not reached
it because it named one function — a `GUARDRAIL_FAILURE` against `LSN-0049`, investigated as such. The
Foundation smoke now waits for both targets within a bound, and the guardrail is a scan, read from
the syntax tree and carrying a null control, of every script that reads Prometheus. `G2-F-014`.
