  Experience Store specification, preflight all lessons, derive requirements and execute baseline.
- Paths: AUTHORIZATION, BASELINE, PLAN, STEPS, canonical checklist/registry, current entry/architecture,
  checkpoint-chain and initial inventory/metadata. No feature implementation belongs to this step.
- Dependencies: clean matching predecessor and current explicit owner authorization. Both observed.
- Success: actual predecessor checks pass, all51 canonical plus134 lesson obligations remain in the
  derived set, baseline91 passes and the initial checkpoint becomes reproducibly valid.

- Stop: unexpected divergence or missing authority. Ordinary failures remain causal rework, not PASS.

## G6-S01 — Experience Store implementation

- Objective: deliver the complete source-bound experience lifecycle with actual persistence and
  authenticated project-scoped HTTP capture, inspection, listing, export, withdrawal and retention.
- Paths: services/experience pure library; packages/contracts and versioned experience schema;
  packages/persistence and a new Alembic revision; apps/api source/store/lifecycle/routes; consumed
  canonical policy; API packaging; registered complete experience suite; runbook/architecture/ADRs.
- Dependencies: S00, ADR-0050 and ADR-0051 before structural behavior. Preserve shared boundaries.
- Design: callers select exact source IDs and explicit storage-only consent, not arbitrary bodies,
  prompts, model output, rights grants or verdicts. A source adapter projects a closed allowlist of
  actual completed runtime/quality facts. Missing model/effort/review/Git observations stay unknown.
  Quality evidence is rehashed/scanned through existing quality contracts; the store never becomes
  another verdict authority. Canonical complete payload scanning precedes durable effects and delivery.
- Persistence: evolve the existing experiences table. Legacy rows remain separately quarantined,
  never silently promoted. New immutable content/digest/provenance and project/source identity are
  database-bound. Capture plus minimal audit fact is one transaction. Request and source uniqueness
  preserve stable retry, refuse conflicting consent and prevent retention reset/resurrection.
- Rights: explicit operational storage consent only. Source permission intersection never grants
  unknown RAG/training/distillation rights; positive reuse grants and downstream execution are not
  introduced. Stored/exported rights remain bound to content. Unauthorized/expired/replayed access,
  unknown fields, private/transcript input and mismatched projects fail closed before effects.
- Retention: consumed finite policy, access denial at expiry independent of the sweeper, bounded
  owned automatic primary-payload removal and authenticated idempotent withdrawal. Minimal finite
  tombstones outlive the capture-age window; old sources cannot be recaptured after tombstone GC.
  Source runs/evidence are not deleted by experience removal. Backup/restore limits are explicit.
- Success: real round-trip, immutability, migration up/down/autogenerate, idempotent concurrent capture,
  access/privacy/rights/retention/deletion/recovery all execute against actual PostgreSQL/HTTP and a
  live completed provider/sandbox/quality workflow. Source presence is insufficient.
- Tests: closed shared contract/policy; pure service positive/adverse decisions; first-persistence
  and scanner failure; literal collection/mandatory suite coverage; real migration and source binding;
  concurrent retries, rollback, clock boundaries, failed dependencies, restart and corrupt bytes;
  signed HTTP and project mismatch; real primary purge and owned background-task shutdown.
- Risks: accidentally copying raw source fields, rights laundering, TOCTOU, unsafe error/log echo,
  retention races, legacy misclassification, SQL/object inconsistency and false functional proof.
- Stop: needed external capability genuinely absent or a material owner choice changes scope. Do
  not weaken correct assertions, scanners, deadlines, security rules or inherited mandatory stages.
