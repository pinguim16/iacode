# Documentation Policy

Documentation is implementation evidence. A task is incomplete when its state cannot be reconstructed from the repository alone.

Record requirement, baseline, plan, concise decisions and alternatives, files, commands, exit codes, duration, failures and corrections, tests, Quality Gates, artifacts, risks, limitations, provenance, status, handoff, and next action.

Do not record secrets, authentication material, or private chain-of-thought. Decision explanations must be short, verifiable summaries.
