## What was learned

Strict JSON prevalidation must preserve transport context. SQL fixtures bind structured data rather
than embed ambiguous colons. Public identities and actual authorization secrets have different
contracts. Privacy and boundedness begin at the SQL projection, not merely at serialization.
Readable summaries cannot replace canonical continuation structure. Freeze all required in-scope
engineering memory before complete immutable assurance; keep later execution outcomes in its ledger.

## What should become a guardrail

The new important confirmed classes already have executable positive/adverse controls and guarded
lesson records: JSON round-trip/types, actual legacy/corruption fixtures, actual runtime credential
projection, real SQL column/byte observations and complete/omitted/empty continuation sections.
The mandatory experience/root/API/integration suites execute them. Removing them would re-admit the
retained failure classes; prose alone never establishes GUARDED. Final whole-Gate freshness and
ordered assurance remain independently enforced by their canonical tools, not by this narrative.
